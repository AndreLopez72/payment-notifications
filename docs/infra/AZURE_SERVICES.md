## Network and identity boundary

The Terraform configuration requires existing private-endpoint subnet and private DNS zone IDs; these network resources are not created because their ownership and topology are not specified. SQL, Service Bus, and Key Vault public network access is disabled in the configuration. This is a provisional security design in A-26 and A-27 and must be checked against Mule platform connectivity before deployment.

Role assignments are scoped to the Service Bus topic (sender), the Salesforce subscription (receiver), and the Key Vault (secret reader). The corresponding workload principal IDs are inputs because A-02 does not confirm how Mule authenticates to Azure. Azure SQL is configured for Entra-only authentication with a supplied Entra administrator; application database users, schema, and grants are not provisioned by this infrastructure code and require a separately approved database migration/access design.

## Cost estimate and validation

An order-of-magnitude monthly estimate cannot be calculated from the supplied documentation without inventing inputs. A-17 identifies the missing Azure region, SQL and Service Bus tiers, redundancy settings, and monthly budget; the Key Vault tier and workspace retention/cost inputs are also not supplied. Therefore this proposal does not claim a monthly amount. Once the platform owner supplies the region, SKUs, redundancy, expected storage/throughput, and retention settings, calculate the estimate for those explicit inputs and record the assumptions here before deployment.

Terraform validation is documented in `infra/README.md`. No resources are deployed by this assessment.
